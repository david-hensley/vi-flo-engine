# Data Dictionary

Explanation of data files and formats

---

## Metadata

Generally stored in a top-level directory alongside raw and processed databases.

### `device_metadata.csv` 
- `unique_ID`: Identifies unique combination of device, station deployment, and location
  - Initial letter 'z' for Zentra data loggers, 'h' for Hobo data loggers
- `watershed`: Name of broad watershed area, usually literal. Named after main gut or bay, normally (e.g. Caledonia, Salt River, Dorothea) 
- `area`: Sub-watershed area name if applicable. Often a tributary basin name (e.g. for Adventure Gut in Bethlehem watershed).
- `site_full`: Full English name of the site including numeric. Lower numbers indicate a higher topographic position in the watershed. 
  - If new sites are established between two integers, decimals must be used e.g. Salt River 0.5
  - Sites are theoretically unified areas of several station deployments e.g. stream gauge, weather station, soil moisture
  - A number is required. Some sites may be established in a downstream area with the possibility of upstream sites in the future, in such cases a Site Name 2 with no Site Name 1 may exist. 
- `site`: Standard abbreviation of full site name. 
  - This is two or three letters for the watershed plus one letter for area if necessary. 
  - Three letters maximum, followed by numbers e.g. sr1, sr0.5, dor1. 
  - Three letters must not be used for watershed abbreviation unless it is certain no "area" will exist for that watershed e.g. Dorothea -> dor. (Would apply mainly to small watersheds)
- `station_type`: Type of information collected by a station, weather, vwc (soil moisture), hydro (stream gauge), pond (pond gauge), etc.
- `station_id`: Concatenates site name and station type for a unique ID for a station
- `mfger`: Manufacturer of device e.g. Meter, Onset, etc.
- `device_serial`: Manufacturer's serial number for the device
- `device_name`: Encoded name for device, usually on manufacturer's software during launching - may be changed
- `lat`: Latitude of deployment
- `lon`: Longitude of deployment
- `elev`: Elevation of these coordinates in meters - autogenerated in attached scripts from DEM
- `deploy_date`: Date-time of actual deployment + functionality of sensor (an hour after initialization)
- `status`: Device status e.g. online (currently working), defunct (assumed broken/lost), decommissioned (removed), local (not connected to internet), nonresponsive (>2 weeks since uplink), etc.
- `last_update`: Date-time of last contact with sensor
- `battery`: Percentage of battery life of device at last known
- `last_visit`: Date of last human field visit
- `interval_min`: Data logging interval in minutes
- `expiry_date`: For Zentra loggers, date of Zentra Cloud subscription expiration
- `timezone`: Named time zone for R, "America/Puerto_Rico" for the Virgin Islands 

### `zentra_ports.csv`
- `sn`: Zentra device serial number
- `port`: Port number, i.e. 1-6
- `type`: Sensor type e.g. weather, vwc (soil moisture)
- `sensor`: Actual sensor model name
- `depth_cm`: Depth of soil sensor deployment, cm (if applicable)
- `status`: Status of sensor if known, e.g. defunct, lost
- `valid_from`: Date-time of first valid sensor reading time (i.e. 1 hour after deployment)
- `valid_to`: Date-time of last valid sensor reading time - if still active, this is NA
